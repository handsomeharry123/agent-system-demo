## 2. 项目识别结果

| 类型 | 技术与用途 |
| --- | --- |
| 运行时 | Node.js，ES Module |
| 语言 | TypeScript 5.9，严格模式、`noUncheckedIndexedAccess` |

### 2.3 启动与初始化方式

```text
1. 复制 .env.example 为 .env，并配置数据库与安全密钥
2. npm install
3. 执行数据库基础建表与升级 SQL
4. npm run seed:admin
5. npm run seed:role-policies
6. npm run seed:permissions
7. npm run seed:dictionaries（需要字典种子时）
8. npm run dev
```

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 开发模式启动，默认 `http://localhost:3000` |
| `npm run typecheck` | TypeScript 类型检查 |
| `npm run build` | 编译到 `dist/` |

## 3. 测试范围与接口映射

### 3.1 登录退出

基础路径：`/api/auth`

- `POST /login/password`
- `POST /sms/send`
- `POST /login/sms`
- `GET /me`
- `POST /logout`

核心规则：密码错误计数，3 次触发验证码标志，5 次锁定 30 分钟；短信 60 秒内限发、摘要存储、过期与一次性消费；JWT 必须同时通过签名和数据库会话校验。

### 3.2 用户中心

基础路径：`/api/users`、`/api/roles`、`/api/permissions`

- 用户列表、元数据、详情、新增、编辑、启停、删除、批量启停、CSV 导出。
- 角色列表、元数据、详情、新增、编辑、删除。
- 角色权限列表、读取权限、覆盖保存权限。

用户、角色与权限接口整体要求登录且具备 `IT_ADMIN` 角色。停用用户应撤销未过期会话；新增用户仅一次返回 bcrypt 初始密码；删除用户/角色会解除关联关系。

### 3.3 审计中心

基础路径：`/api/audit/operation-logs`

- 日志列表、筛选元数据、用户选项、详情。
- 事件刷新和 CSV 导出。
- `operationAuditMiddleware` 对平台写操作记录审计结果。

需同时测试“审计日志查询接口”和“各业务写接口是否正确产生日志”。

### 3.4 系统配置

基础路径：`/api/system-config/dictionaries`、`/api/system-config/models`

- 数据字典和字典项 CRUD、启停、Excel 导入导出。
- 模型配置 CRUD、临时连接测试、已保存配置连接测试。
- 两组接口均要求 `IT_ADMIN`。

注意：前端存在第三方评测平台配置页面，但当前后端没有对应路由，不纳入后端已实现功能通过率，应作为接口缺口记录。

### 3.5 智能体接入中心

基础路径：`/api/agent-access`

- 元数据、申请列表/详情。
- 草稿保存、提交、删除、撤回、开始审核、审核通过/退回。
- 文件上传和授权下载。
- 新建阶段和审核阶段连通测试。
- SDK/OTEL 插桩信息签发。

核心链路：申请数据及版本 → 状态历史 → 审核记录 → 审核通过后自动生成台账、台账版本和生命周期事件。

### 3.6 统一台账中心

基础路径：`/api/ledger`

- `GET /overview`：台账统计总览。
- `GET /agents`：列表、筛选、分页。
- `PATCH /agents/:id/status`：管理员禁用/启用。

注意：前端台账详情、风险分级、360 画像功能大于当前后端路由能力；缺失的后端详情/风险接口不计入已有接口测试通过率，但需列为范围差距和联调风险。

## 4. 主要质量风险

### 4.1 P0 高风险

1. **认证绕过与会话失效**：仅验证 JWT 而未验证数据库会话、撤销后仍可使用、用户停用后会话未失效、会话和用户状态不同步。
2. **授权粒度不一致**：部分模块使用角色授权，功能权限目前主要用于前端展示。需验证普通用户不能直接调用管理接口，并评估“有功能权限但非 IT_ADMIN”与“有角色但无功能权限”的冲突。
3. **智能体接入状态机和并发**：重复提交、撤回后审核、双人审核、通过后再次审核，可能导致状态历史、审核记录和台账重复或错乱。
4. **审核通过跨表事务**：申请审核、智能体主状态、台账、版本、生命周期事件和同步时间必须原子提交；任一步失败必须全部回滚。
5. **用户启停/删除一致性**：账号状态、角色、数据策略、密码、会话和审计日志需要一致，不能残留可用会话或孤儿关联。
6. **模型 API Key 保护**：密钥加密、掩码、最后四位、更新语义、连接测试、日志和错误路径均可能泄露明文。
7. **审计覆盖白名单遗漏**：`describeOperation` 未映射的接口会直接跳过。必须验证登录/退出、首页、用户中心、审计中心、系统配置、智能体接入和统一台账的关键接口，而不是只验证 `aud_operation_log` 中已有记录。

### 4.2 P1 高风险

1. multer 使用内存存储，30MB 并发上传可能造成进程内存压力或拒绝服务。
2. Excel 导入可能受公式、畸形工作簿、巨量行、重复数据、类型混淆影响；需要验证事务回滚。
3. CSV/Excel 导出存在公式注入、字符编码、字段转义和越权导出风险。
4. 短信接口只有 60 秒内限发逻辑时，仍需验证按 IP/手机号的滥用、验证码暴力破解和开发验证码泄露。
5. 模型连接测试会访问用户输入 URL，存在 SSRF、内网探测、重定向、DNS 重绑定和超时资源耗尽风险。
6. 接入连通测试及文件下载涉及外部地址和凭证，存在 SSRF、敏感数据泄露及越权读取风险。
7. 审计中间件在响应完成后异步写日志时，可能漏记、重复、记录错误结果或在失败时影响业务进程。
8. 台账统计 SQL 与列表筛选口径不一致、除零、空数据和时区边界可能导致错误统计。

### 4.3 工程与可运维风险

- 当前无自动化测试、覆盖率、迁移工具和 CI 门禁。
- 部分路由文件代码高度压缩，复杂 SQL 与业务逻辑耦合，审查和分支覆盖困难。
- 错误处理依赖 `statusCode` 动态属性，未统一错误类型，存在错误码退化为 500 的风险。
- JSON 请求上限 32KB，长表单、复杂权限列表或接入配置可能意外超过限制。
- CORS 仅允许单一前端来源；反向代理、预检、生产域名配置错误会阻断调用。
- `trust proxy = 1` 会影响审计 IP 和限流基础，代理拓扑配置错误可导致 IP 伪造。

## 5. 测试分层方案

### 5.1 L0 静态检查、构建和数据库脚本检查

- 执行 `npm run typecheck` 与 `npm run build`。
- 检查依赖漏洞、环境变量缺失、默认密钥、日志敏感信息。
- 在空库按顺序执行基础 SQL、升级 SQL和全部 seed，验证首次执行成功。
- 重复执行可重入脚本，验证不重复创建、不覆盖业务数据。
- 校验数据库字符集、时区、外键/唯一键、索引和备注；验证生产编译产物可启动。

### 5.2 L1 单元测试

建议工具：Vitest；数据库访问、Crypto、时间、外部 HTTP 和文件解析使用可控替身。

优先对象：

- Token 摘要、短信验证码摘要、JWT 载荷和会话过期计算。
- 用户前端 DTO 映射、权限码映射、参数解析和字段校验。
- 初始密码生成和中文拼音边界。
- 模型密钥加解密、掩码、最后四位处理。
- 状态转换规则、台账状态/风险/统计映射。
- CSV 转义、防公式注入、下载文件名和 Excel 行校验。
- API 统一响应和错误状态映射。

目标覆盖率建议：整体核心代码行覆盖率 ≥ 80%；认证、授权、加密、状态机和数据转换分支覆盖率 ≥ 90%。

### 5.3 L2 路由/API 组件测试

使用独立 Express app 和隔离测试库或可回滚数据库事务，覆盖：

- 每个接口的成功、必填缺失、格式错误、边界长度、非法枚举、空结果。
- 无 Token、伪造 Token、过期 Token、已撤销会话、无角色、过期角色。
- 404、409、423、上传超限、数据库异常、非预期异常的响应格式。
- 分页最小/最大值、负数、超大值、特殊字符搜索和 SQL 注入输入。
- JSON 32KB 临界值和 Content-Type 异常。
- CORS 允许来源、拒绝来源、OPTIONS 预检。

### 5.4 L3 数据库集成与事务测试

- 使用 MySQL 8 真库，不使用 SQLite 替代关键 SQL 行为。
- 每条写接口验证业务表、关联表、状态历史、会话和审计表。
- 在事务各关键 SQL 点注入失败，验证完整回滚。
- 使用两个数据库连接模拟并发提交、审核、启停、删除和权限覆盖保存。
- 验证唯一键冲突、行锁、死锁重试策略、隔离级别和时区。
- 验证软删除数据不会被列表/详情/权限查询返回。

### 5.5 L4 前后端契约与业务链路测试

- 将 `002.前端代码/src/services` 的请求与后端真实路由逐项比对。
- 校验字段名、枚举值、分页结构、空值、日期格式、错误消息和 HTTP 状态。
- 文件接口校验 `Content-Type`、`Content-Disposition`、字符编码和鉴权。
- 覆盖登录 → 用户/角色/权限 → 接入申请 → 审核 → 台账 → 审计查询的完整链路。
- 将前端存在而后端缺失的能力列为契约差距，不通过 Mock 掩盖。

### 5.6 L5 非功能与安全测试

- **性能**：登录峰值、列表查询、10 万审计日志、1 万用户/台账、批量状态更新、并发文件导入。
- **稳定性**：数据库短暂断连、连接池耗尽、外部模型超时、进程重启、重复请求。
- **安全**：OWASP API Top 10、越权、SQL 注入、XSS 持久化、SSRF、上传、CSV 公式注入、JWT、暴力破解、敏感日志。
- **资源**：32KB JSON、30MB 文件、多文件并发、巨型 Excel、慢请求和客户端中断。
- **可观测性**：健康检查、结构化日志、错误关联标识、审计完整性、敏感字段脱敏。

## 6. 分模块测试重点

### 6.1 登录退出

- 正确/错误密码、未知账号、停用账号、已删除账号、空密码。
- 失败 1～5 次计数，3 次验证码标志，5 次锁定，锁定期和解锁边界。
- 成功登录重置失败状态；并发错误登录不会丢失计数。
- 短信发送限频、手机号归属、验证码过期、错误、重放和成功消费。
- JWT 签名、`sub/sid` 缺失、会话摘要不符、已撤销/过期会话。
- 退出仅撤销当前会话还是全部会话的预期确认；退出幂等。
- 登录和失败日志中的 IP、User-Agent、方式、结果准确。

### 6.2 用户中心

- 用户列表/元数据/详情的分页、筛选、数据范围和软删除过滤。
- 新增用户的唯一约束、部门/角色有效性、初始密码一次性返回与 bcrypt 存储。
- 编辑时登录名/工号/手机号冲突、角色替换、空角色和不存在角色。
- 启停单个/批量账号，停用立即撤销所有有效会话。
- 仅已停用用户可删除，删除后解除角色和数据权限关联。
- 批量按 IDs 与按筛选范围的语义、空集合和部分无效 ID。
- CSV 导出的筛选一致性、编码、转义、公式注入与权限。
- 系统角色保护、角色删除关联计数、数据范围策略、权限覆盖保存原子性。

### 6.3 审计中心

- 所有范围内写接口成功/失败是否记录正确操作日志。
- 密码、短信验证码、JWT、模型密钥、接入凭证、文件内容不得进入日志。
- 列表复合筛选、时间边界、分页稳定排序、详情不存在。
- 用户选项和元数据的数据权限。
- 刷新事件的幂等性；并发刷新不重复写入。
- 按筛选/ID 导出，非法 ID、超大量、中文和危险单元格内容。
- 审计写入失败不得静默破坏业务，但必须可监控和告警。
- 以信息科管理员、医院领导、科室管理员、普通用户四类真实 Token 发起授权操作，按 `user_id` 回查新增日志，校验操作者快照、角色快照、组织、模块、方法、路径和成功/失败结果。
- 对本轮所有真实后端路由建立审计映射覆盖表；每个关键路由至少有一条成功日志，写接口还需有一条失败日志。
- 登录成功/失败若归属登录审计表，需要与操作日志页面展示口径形成明确契约；不能因分表而在前端表现为用户无任何活动。
- 对 `describeOperation()` 返回 `null` 的范围内路由设置测试门禁，避免新增业务接口静默脱离审计。

### 6.4 系统配置

- 字典码/名称唯一性、启停、更新、删除及被引用约束。
- 字典项值/标签唯一性、排序、父字典状态与子项状态关系。
- Excel 文件类型、大小、空表、错列、重复、超长、公式、畸形结构及全量回滚。
- 导出内容与筛选一致，文件可被常见办公软件正确打开。
- 模型配置字段校验、名称版本冲突、密钥加密和掩码。
- 模型 URL 仅允许安全协议和允许目标；阻止本机、内网、云元数据与重定向 SSRF。
- 连接测试成功、非 2xx、TLS 错误、DNS 错误、超时、慢响应和响应过大。
- 删除/编辑/测试已不存在或被并发删除的模型。

### 6.5 智能体接入中心

- 申请人、管理员、科室管理员的数据范围和操作权限。
- 保存草稿与提交的数据校验差异；版本号和修订记录。
- 附件 0B、临界 30MB、超限、MIME/扩展名不一致、特殊文件名和路径穿越。
- 文件 UUID 猜测、跨用户下载、已删除申请附件下载和响应头安全。
- 连接测试的地址/凭证校验、SSRF、防重放、超时和审计脱敏。
- 草稿删除、已提交撤回、开始审核、退回、重提、通过的合法状态矩阵。
- 两个审核人并发操作、重复请求和网络重试下的幂等性。
- 审核通过后智能体、台账、版本、生命周期事件、状态历史均正确；失败全部回滚。
- 插桩 Key 的不可预测性、用户隔离、敏感输出和重复签发策略。

### 6.6 统一台账中心

- 总览在空库、单部门、跨部门、多状态数据下的统计口径。
- 部门覆盖率、调用量、告警、在线率分子分母和小数精度。
- 列表分页稳定排序、组合筛选、关键词特殊字符和数据权限。
- 接入审核通过生成唯一台账编号和唯一版本，重复审核不重复生成。
- 管理员禁用必须有原因，普通用户 403；启用后的生命周期和运行状态。
- 两管理员并发启停、重复启停、资源不存在和行版本一致性。
- 状态变更必须记录生命周期事件和操作审计，操作者准确。

## 7. 关键状态与权限矩阵

### 7.1 智能体接入状态

测试设计时应从代码和需求固化完整状态表，至少验证：

| 当前状态 | 允许动作 | 禁止动作 |
| --- | --- | --- |
| 草稿 | 编辑、保存、提交、删除 | 审核通过 |
| 已提交/待审核 | 撤回、管理员开始审核 | 删除草稿、申请人改业务字段 |
| 审核中 | 管理员通过或退回 | 申请人删除、重复开始审核 |
| 已退回 | 申请人编辑、重新提交 | 直接生成台账 |
| 已通过 | 查看、同步台账结果 | 再次审核、撤回、删除 |
| 已撤回 | 按需求允许重新编辑/提交 | 管理员继续原审核 |

实际枚举名称以数据库和 API 为准；若需求与代码不一致，应在用例评审前形成决议。

### 7.2 权限角色

| 能力 | IT 管理员 | 医院领导 | 科室管理员 | 普通用户/申请人 |
| --- | --- | --- | --- | --- |
| 用户/角色/功能权限管理 | 允许 | 拒绝 | 拒绝 | 拒绝 |
| 审计日志全量查看/导出 | 按需求确认 | 按需求确认 | 仅范围内 | 拒绝或本人 |
| 系统字典/模型管理 | 允许 | 拒绝 | 拒绝 | 拒绝 |
| 创建接入申请 | 允许 | 按需求 | 允许 | 允许 |
| 审核接入申请 | 允许 | 按需求 | 按范围 | 拒绝 |

标记“按需求确认”的权限必须在测试用例设计前由产品确认，后端不能只依赖前端隐藏按钮。

## 8. 测试环境与数据管理

### 8.1 环境要求

- 独立 MySQL 8 测试实例，启用 utf8mb4，与目标生产时区一致。
- 测试、开发、生产使用不同数据库、JWT Secret、SMS Pepper 和模型密钥加密材料。
- 外部模型连接使用专用 Mock Server，禁止自动化测试访问真实生产模型或内网资产。
- 文件测试使用隔离存储/测试目录，执行后可清理。
- 所有测试可重复运行，固定时间和随机数的用例应可控制。

### 8.2 数据准备

- 全角色用户、过期角色、停用和软删除用户。
- 每个接入状态至少两条记录，支持并发测试。
- 台账覆盖生命周期、运行状态、风险等级和部门组合。
- 大数据集：1 万用户、10 万审计日志、1 万台账记录。
- 导入文件：合法、小/大、空、损坏、错表头、重复、公式、中文。
- 敏感数据标记样本，用于自动扫描响应、日志、导出是否泄露。

数据清理优先使用事务回滚或按测试运行 ID 精确删除，禁止对共享库执行无条件清表。

## 9. 执行阶段与优先级

| 阶段 | 测试内容 | 通过条件 |
| --- | --- | --- |
| T0 环境与脚本 | 建库升级、Seed、类型检查、构建、生产启动 | 全部成功且可重复 |
| T1 API 冒烟 | 健康、登录、用户查询、接入提交审核、台账查询 | 100% 通过 |
| T2 功能与事务 | 六模块接口、状态机、权限、回滚 | P0 100%，P1 ≥ 95% |
| T3 安全与性能 | 越权、SSRF、上传导出、并发和大数据 | 无高危遗留 |
| T4 联调回归 | 前端契约、跨模块链路、缺陷回归 | 无未关闭 P0/P1 |

P0：认证授权绕过、敏感信息泄露、数据破坏、审核/台账事务错误、服务不可用。P1：核心业务错误、越权边界问题、文件与导入导出严重异常。P2/P3 分别为有替代路径的问题和轻微体验/提示问题。
