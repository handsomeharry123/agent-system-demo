### 3.2 范围边界

- 不把需求管理、立项申报、资源中心、评测中心、编排、监控、安全治理、数据资产等模块作为本轮主体。
- 若登录、菜单、权限或智能体审核同步台账影响这些模块，只做必要的冒烟回归。
- 系统配置中的“数据字典”和“模型配置”有真实后端；“第三方评测平台配置”当前主要由前端数据承载，应单独标记为原型功能，不误判为完整持久化能力。
- 智能体接入普通注册流程使用真实后端；智能填写/对话辅助包含较多前端 Store 与演示逻辑，需区分真实接口结果和模拟结果。
- 统一台账总览、列表、启停使用真实后端；详情、风险分级、Demo 报告等存在 Mock 数据，测试报告应明确数据来源。

## 4. 主要质量风险

### 4.1 P0 高风险

1. **前后端权限不一致**：前端按 `permissionCodes` 控制菜单和路由，后端部分接口按角色控制。需验证无权限用户既看不到入口，也不能通过直达 URL 或手工请求越权。
2. **登录态存在本地缓存窗口**：页面初始状态读取 `auth_user`，随后才调用 `/auth/me` 校验 Token。需测试伪造、过期、撤销 Token 以及旧缓存权限造成的短暂越权或页面闪现。
3. **用户停用与会话撤销**：用户中心停用账号后，已登录页面必须在下一次请求时可靠退出，不能继续访问敏感页面。
4. **智能体接入状态机**：草稿、提交、审核中、退回、通过、撤回、删除之间按钮和页面必须与后端允许的状态一致；重复点击、刷新、并发审核不得制造重复记录。
5. **审核通过同步台账**：接入审核成功后自动进入台账。前端需正确处理成功、事务失败、重复审核以及刷新后的最终状态。
6. **敏感模型密钥**：模型 API Key 不能在列表、详情、错误提示、浏览器日志或网络响应中明文回显；编辑时的掩码不得被当作新密钥提交。
7. **审计记录主体和覆盖完整性**：不能只验证管理员日志。医院领导、科室管理员、普通用户登录并访问首页、接入中心、台账等授权模块后，必须产生对应用户、角色、组织、模块、操作结果和路径的日志；否则按 P0 审计缺失处理。

### 4.2 P1 高风险

1. 文件上传、Excel 导入、CSV/Excel/PDF 下载的类型、大小、空文件、恶意文件名、重复文件和中文文件名兼容性。
2. 用户、角色、权限多层联动后，菜单、按钮和接口权限是否即时刷新。
3. 用户/角色删除、停用和批量操作的二次确认、部分失败、重复操作及页面数据回滚。
4. 接入注册长表单字段多，草稿恢复、编辑回填、必填校验、跨步骤数据保留容易失真。
5. 接入连通性测试涉及异步反馈和凭证，需防止 UI 超时后误显示成功、重复触发、凭证泄露。
6. 台账筛选、分页、统计总览的数据口径一致性，以及管理员启停后详情、列表、总览同步刷新。
7. 审计日志导出应遵循当前筛选/选中范围，且不能因 CSV 公式注入危害打开文件的终端用户。

### 4.3 工程风险

- 约 11 万行前端 TypeScript，存在超大组件（如首页文件超过一万行、接入/台账多个页面超过千行），回归影响面大。
- TypeScript 未开启严格模式，允许隐式 `any`，纯构建检查不能替代运行时边界测试。
- API 封装分散，各服务对 401/403、非 JSON 响应和网络超时的处理不完全统一。
- 项目没有现成单元测试、组件测试和 E2E 测试，自动化需要从基础设施开始建设。
- 真实接口、Mock、浏览器存储三种数据源并存，易出现刷新丢失、跨账号串数据和错误的“测试通过”。

## 5. 测试分层方案

### 5.1 L0 静态检查与构建门禁

目标：尽早发现类型、导入、路由和生产构建问题。

- 执行 `npm run build`，要求 TypeScript 与 Vite 构建成功。
- 检查路由定义、重复路径、参数编码、未知路径回退、菜单与路由映射。
- 检查敏感信息硬编码、控制台输出、生产环境变量和 Source Map 策略。
- 建议后续补充 ESLint、依赖漏洞扫描和未使用代码检查；本轮只规划，不实施。

### 5.2 L1 纯函数与 Hook 单元测试

建议工具：Vitest、React Testing Library、MSW。

优先对象：

- 权限判断、角色落地页、登录态恢复和退出清理。
- 用户列表查询参数、初始密码结果展示、状态映射。
- 表单校验、状态到按钮的映射、智能体名称匹配、头像工具。
- 字典/模型/接入/台账 API 请求参数和错误映射。
- CSV/Excel 下载文件名、筛选参数、Blob 生命周期。
- 接入注册字段转换、草稿合并、审核状态展示。

目标覆盖率建议：新增核心逻辑行覆盖率不低于 80%，权限、状态转换和数据转换分支覆盖率不低于 90%。

### 5.3 L2 组件与页面集成测试

使用 Mock Service Worker 控制 API 正常、业务失败、401、403、409、500、超时和断网场景。

- 登录表单：校验、提交中禁用、错误次数提示、锁定提示、短信倒计时。
- 受保护路由：无会话、有效会话、缓存会话、失效会话、无模块权限。
- 用户与角色：筛选分页、抽屉/弹窗、增改、启停、删除、批量操作、权限树保存。
- 审计日志：复合筛选、详情、刷新、全选/跨页选择、导出。
- 系统配置：字典和字典项 CRUD、导入导出、模型密钥表单和连接测试。
- 智能体接入：长表单、附件列表、草稿/提交/编辑/撤回/审核、连接测试。
- 台账：总览、列表筛选、详情跳转、启停确认及错误恢复。

### 5.4 L3 前后端契约与集成测试

- 以真实 `004.后端代码` 和独立测试库运行，不使用生产或共享演示数据。
- 校验请求方法、URL、参数名、枚举、分页结构、错误码、下载响应头和空值语义。
- 对每个真实 API 至少覆盖成功、参数错误、未登录、无权限、资源不存在和冲突。
- 建立“页面字段—请求字段—数据库字段”核对表，重点覆盖用户、角色、字典、模型、接入注册与台账。
- 明确前端已调用但后端不存在的地址，禁止将静态 Mock 成功当作契约通过。

### 5.5 L4 浏览器端到端测试

建议浏览器：Chromium 为主门禁，Firefox/WebKit 做每日或发布前回归；至少补充 Chrome 最新稳定版人工兼容测试。

P0 主链路：

1. 管理员密码登录 → 进入管理员首页 → 退出 → 受保护页回到登录页。
2. 普通用户登录 → 无权访问用户中心/系统配置 → 直达 URL 也被拒绝。
3. 管理员新建用户 → 分配角色 → 新用户登录 → 停用用户 → 会话失效。
4. 新建角色 → 配置功能权限 → 关联用户 → 重新登录后菜单和路由权限生效。
5. 查询审计日志 → 查看详情 → 按筛选导出 → 校验下载内容。
6. 新建字典/字典项 → 导出 → 导入 → 启停 → 删除约束校验。
7. 新建模型配置 → 测试连接 → 编辑 → 删除，确保密钥全程不泄露。
8. 创建智能体接入草稿 → 编辑 → 上传材料 → 连通测试 → 提交 → 管理员审核通过。
9. 审核通过后进入统一台账 → 列表可查 → 查看详情 → 管理员禁用/启用 → 状态一致。
10. 智能体接入退回链路：提交 → 审核退回 → 申请人修改重提 → 审核通过。

### 5.6 L5 非功能测试

- **性能**：登录和常用列表首屏；1 万用户、10 万审计日志、1 万台账数据下的分页与筛选；超大前端包的首屏加载。
- **安全**：XSS、开放重定向、路由越权、Token 缓存、CSV 公式注入、上传文件、敏感字段回显、浏览器控制台泄密。
- **兼容性**：1920×1080、1440×900、1366×768；125%/150% 缩放；中文输入法；长文本和极端表格列。
- **可访问性**：键盘操作、焦点管理、表单标签、错误可感知性、颜色对比度。
- **可靠性**：重复提交、刷新、后退/前进、断网重连、接口超时、后端重启、并发操作。

## 6. 分模块测试重点

### 6.1 登录退出

- 密码和短信两种模式切换、必填/格式校验、回车提交、防重复提交。
- 密码错误 3 次验证码提示、5 次锁定提示、锁定到期恢复。
- Token 缺失、篡改、过期、服务端撤销、用户停用后的页面行为。
- 登录后按角色跳转；原始目标页恢复；退出后历史返回不能恢复敏感页面。
- 多标签页登录/退出一致性和本地缓存清理。

### 6.2 用户中心

- 查询、组合筛选、分页、空态、异常态、CSV 导出范围。
- 创建用户字段边界、账号/工号/手机号重复、中文姓名生成初始密码、初始密码仅展示一次。
- 编辑用户和角色、单个/批量启停、停用撤销会话、删除前置条件。
- 角色 CRUD、系统角色保护、关联用户角色删除、数据范围、功能权限树父子联动。
- 不同角色下菜单、按钮、路由、API 四层权限一致。

### 6.3 审计中心

- 时间、组织、模块、操作类型、用户和关键词组合筛选。
- 列表分页与详情快照一致；刷新事件后的增量和重复数据。
- 全量、当前筛选、选中项导出；中文、逗号、换行和公式前缀内容。
- 普通用户不可查看或导出超出权限范围的日志。
- 写操作产生审计日志时，操作者、IP、结果、对象、请求摘要准确且敏感字段脱敏。
- 使用信息科管理员、医院领导、科室管理员和普通用户分别执行真实业务动作，逐个按用户筛选并断言新日志存在，禁止仅断言日志总数大于零。
- 建立“受测后端路由—审计模块—操作类型”覆盖矩阵；未映射路由、前端 Mock 操作和登录行为应明确暴露为缺口。
- 验证默认倒序分页不会造成“只有管理员日志”的误判，同时验证指定用户筛选结果准确。

### 6.4 系统配置

- 字典/字典项唯一性、状态联动、删除约束、排序、分页、导入事务性。
- Excel 空表、错列、重复值、超限、中文、公式和畸形文件。
- 模型名称版本唯一性、URL/手机号/密钥校验、连接成功/失败/超时。
- 密钥掩码、更新留空语义、列表/详情/日志/错误均不得明文泄露。
- 评测平台配置的前端持久化边界和刷新行为需单独记录。

### 6.5 智能体接入中心

- 列表、状态筛选、申请人/管理员数据范围。
- 新建、保存草稿、编辑、提交的字段完整性和回填一致性。
- 附件类型、大小（服务端上限 30MB）、数量、中文名、重复上传、下载授权。
- 接入方式、端点、认证信息与连通测试的组合矩阵。
- 草稿删除、已提交撤回、开始审核、退回、通过及非法状态操作。
- 双击提交、双人审核、刷新重试、请求超时后的幂等与最终状态。
- 审核通过后台账编号、版本、生命周期事件和页面跳转。

### 6.6 统一台账中心

- 总览统计和列表数据口径，部门覆盖率、调用、告警、在线率边界值。
- 关键词、部门、类型、状态、风险等级组合筛选及分页。
- 列表—详情—360 画像的数据一致性，未知/空值展示。
- 管理员禁用必须填写原因，启用后状态正确；普通用户操作入口和接口均拒绝。
- 接入审核同步失败不应展示幽灵台账；重复审核不产生重复台账或版本。
- 大数据量、快速切换筛选、接口乱序返回下不展示过期结果。

## 7. 测试环境与数据

### 7.1 环境

- 前端：`http://localhost:3001`
- 后端：`http://localhost:3000`
- 数据库：独立 MySQL 8 测试实例，禁止复用生产库。
- 建议准备 CI 环境，使用固定 Node LTS 版本；当前本机版本需记录到执行报告。

### 7.2 测试角色

- 信息科管理员：全范围管理权限。
- 医院领导：只读与统计访问。
- 科室管理员：本部门数据范围。
- 普通用户/申请人：提交与查看本人数据。
- 无功能权限用户、停用用户、角色过期用户。

### 7.3 数据集

- 每种角色至少 2 个用户、多个部门、同名人员、长姓名和特殊字符。
- 接入申请覆盖全部状态，每种接入模式至少 1 条。
- 台账覆盖试运行、运行、禁用、离线及不同风险等级。
- 字典/字典项覆盖重复、禁用、被引用、中文和边界长度。
- 审计日志覆盖成功/失败、不同模块、不同时间、敏感输入。
- 文件覆盖 0B、临界大小、超过 30MB、合法/非法扩展名、中文与特殊文件名。

## 8. 执行阶段与优先级

| 阶段 | 内容 | 通过条件 |
| --- | --- | --- |
| T0 环境验收 | 构建、启动、健康检查、测试库、账号 | 环境稳定且数据可重置 |
| T1 冒烟 | P0 登录、用户查询、接入提交审核、台账查询 | 100% 通过 |
| T2 功能与契约 | 六模块主功能、异常和权限 | P0 100%，P1 ≥ 95% |
| T3 专项 | 安全、文件、兼容性、性能、可靠性 | 无阻断发布问题 |
| T4 回归 | 缺陷修复、跨模块链路、生产构建 | 无未关闭 P0/P1 |

缺陷优先级：P0 为登录/权限绕过/数据破坏/核心链路不可用；P1 为核心功能错误或敏感信息风险；P2 为有替代路径的功能问题；P3 为样式和轻微易用性问题。

## 9. 准入与准出标准

### 准入

- 需求范围与页面/API 映射确认完成。
- 前后端可稳定启动，数据库脚本及种子数据可重复执行。
- 六模块至少有一套可独立使用的角色和业务数据。
- `npm run build` 通过；已知阻断问题有明确处置。

### 准出

- P0 用例 100% 通过，P1 用例通过率不低于 95%。
- 无未关闭 P0/P1 缺陷；P2 缺陷有风险接受人与上线后计划。
- 权限矩阵、接入到台账主链路、文件处理和敏感数据专项完成。
- Chrome 主流程通过，目标分辨率无阻断问题。
- 测试报告区分真实后端、Mock 与浏览器存储结果，不混报覆盖率。
